## 0. 要解决什么

过往段子常见问题：**太短、短平快、一句话冷笑话、没有铺垫与余味**。  
本方案把「段子」定义为**短叙事笑话**（微型故事），不是梗图配文或单句 punchline。

## 1. 生成流程（强制四步）

```
素材收集 → 结构设计 → 撰写 → 自检
   ↓           ↓         ↓      ↓
inbox/     structure  draft   checklist
```

### 1.1 素材收集（`inbox/`）

每条素材至少写清：

| 字段 | 说明 |
|------|------|
| 来源 | 热点/时事/职场/币圈日常/个人观察（标平台与链接若有） |
| 事实 vs 夸张 | 事实一句；可夸张空间一句 |
| 情绪核 | 尴尬 / 反差 / 自嘲 / 荒诞 / 无力感 等，只选一个主核 |
| 禁区 | 人身攻击、未成年、仇恨、未核实指控、交易诱导 |

产出文件：`inbox/I-YYYYMMDD-NN.md`（只收集，不写成品）。

### 1.2 结构设计（先结构，后成文）

动笔前必须填满下列槽位（可写在 draft 文首 YAML 或同目录 `structure.md`）：

1. **场景**（谁、在哪、在干什么）— 至少两句可展开的具体细节  
2. **铺垫期待**（读者以为会怎样）  
3. **拐点**（哪里开始不对劲）  
4. **反转**（真正好笑/扎人的落点，须与铺垫有因果，不能硬拐）  
5. **余味**（反转后多留 1～2 句：自嘲、回扣标题、或把笑点落到现实）  
6. **长度目标**：正文 **180～450 字**（不含标题）；低于 120 字默认判「太薄」重写

禁止：先写 punchline 再往前硬凑两句。

### 1.3 撰写

- 只用 `templates/段子成稿.md`  
- 成稿路径：`samples/`（试稿）或后续 `drafts/D-YYYYMMDD-NN/draft.md`  
- 语气：口语、可转发；可结合热点，但**热点是布景不是标题党**  
- 作者标注：`author: 段子创作`（或未来独立 Agent 名）

### 1.4 自检

先跑「机械自检清单」（见 §3），全过再交本人品鉴。  
机械自检不过 → 回 1.2 改结构，不直接改措辞糊弄字数。

## 2. 「深度」标准

### 2.1 达标（须同时满足）

| 维度 | 达标样子 |
|------|----------|
| 铺垫 | 有具体场景与人物动作；读者能预演「正常结局」 |
| 反转 | 与铺垫同一逻辑链上的意外；重读前文有伏笔感 |
| 余味 | 笑完还剩一点刺或共鸣（身份、机制、时代感），不是「哈哈哈然后呢」 |
| 完整度 | 像一则微型故事，可单独发；不是评论区一句回复 |
| 热点用法 | 热点提供情境或反差材料，不靠点名流量词硬搞笑 |

### 2.2 太薄（任一即退回）

- 只有 punchline，前文可删不影响笑点  
- 纯谐音 / 纯玩梗 / 「然后他就…」无因果  
- 字数注水：形容词堆砌、无关清单、重复同义句  
- 嘲讽落到具体真人隐私或未核实指控  
- 结尾用「你觉得呢」「绝了」「无语」等空壳收束  

### 2.3 一句话对照

> **薄**：一个包袱。  
> **深**：一个小世界里，期待被合理地打碎，碎完还能听见回声。

## 3. 评判拆分

### 3.1 可机械自检（Agent / 脚本可做）

- [ ] 正文汉字数 ∈ [180, 450]（可放宽到 150～500，但 <120 硬失败）  
- [ ] 文首结构槽位 6 项齐全  
- [ ] 含「场景具体名词」≥ 3（地点/物品/产品名/职位等，非「有个人」「某天」）  
- [ ] 反转段落后仍有 ≥ 1 句余味（非空壳收束词）  
- [ ] 未出现禁区关键词表（可配置）  
- [ ] 未同时冒充资讯稿字段（无「偏多/偏空」「验证失效」等交易话术）  
- [ ] `author` 字段存在且非资讯创作官  

### 3.2 必须本人品鉴

- 反转是否「聪明」还是「强行」  
- 余味是共鸣还是说教 / 贩卖焦虑  
- 是否冒犯到不该冒犯的人（尺度）  
- 结合热点时是否过时或踩雷  
- **值不值得发**（最终上架权只在本人）
